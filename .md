# Challenges

## Deploying to Production

- Initial challenge when it came to proper configuration between MinIO, our chosen object storage server, which resulted to all media not displaying such as profile picture, display previews, content thumbnails, etc.

- Remedying bugs in production that isn't found in local such as display runtime not properly displaying live schedules, user session kicked out upon reload, etc.

## Performance Optimization

- Before our consultation with our advisors, initial load time and general app performance was so slow. After back and forth with advisors, we improved the overall performance of the app which was due to unnecessary and redundant global API calls, lazy loading, code splitting, etc--all of which we've cleaned up.

## Constant Scope Validation

- It was also a challenge for us to decide which features to remove or keep based on the app's core mission, which is to be a reliable digital signage management solution for disseminating information within the department. Due to this constant scope validation, it added lots of re-planning which costed time, but ultimately led to the removal of the Block Editor in place of an AI Chat that much better supplements the core mission of the app.

# Identifying Future Work/Improvements

## Choice of Framework/Tech Stack

- Future improvements could be selecting a framework more suitable for DCISM server instead of NextJS, which is primarily used for Server-Side Rendering (SSR). From what we've observed, even as simple as just React combined with React Query (formerly known as Tanstack Query) would be sufficient and would introduce less overheads that NextJS has.
